# Factory 2.2.0 — release record

2.2.0 is the release after 2.1.3 ([v2.1-release.md](v2.1-release.md)). It carries PR #8:
MV-3 of the plan made after the first complete production run on 2.1.2
(`new-game-20260927-155337-3c1781`), the root cause of the long-standing process-liveness
test failure, and a decidable template-contract versioning rule. What changed, and what an
upgrade will show, is in [CHANGELOG.md](../CHANGELOG.md) under 2.2.0.

## Why 2.2.0 - the compatibility evidence

The version was decided on what consumes the changed behaviour, not on the size of the
change. Every consumer of the release directory, the package list and the verification
verdict in the Factory and in the pinned template was read:

| Consumer | Reads | After this release |
|---|---|---|
| `wgf_release` (`_collect`, `_manifest`) | `packages.json`, the zips, `checksums.txt` | reads what is shipped; refuses a foreign package |
| `scripts/golden/{summary,browser,compare}.py` | `manifest.packages` generically; the primary platform's zip | unchanged: the primary zip is the target |
| template `scripts/release/make-manifest.mjs` | `packages.json` | runs after the pruning, lists what ships |
| template `scripts/publish/make-publication.mjs` | `game.config.yaml` platforms; names `<id>.zip` | never opens the zip: does not fail |
| template `.github/workflows/publish.yml` | `release/<id>/poki.zip` | the target of a Poki-primary game: present |
| template `.github/workflows/release.yml` | its own build and packaging | independent of the Factory's draft |
| `wgf_strategy` | writes `platforms[]` | always exactly one `required` (`planner.py`), so the new verify failure for a second required platform does not arise from the Factory's own strategy |

No consumer breaks; no schema, workflow definition, configuration key or `CONTRACT_VERSION`
changed. The release adds API - check ids `platform.build-target:<id>` and
`policy.device-performance`, refusal code `package-not-built`, release metadata
`not_packaged`, liveness field `output_silence_seconds`, and `template_contract.build_target`,
`CONTRACT_LOG`, `CONTRACT_DIGEST` - so it is **minor**. It is not major: nothing documented as
working becomes incompatible. The removed packages never worked on their portals (recorded as
a defect in [v1-usable.md](v1-usable.md), "One build for every platform"), and the one
documented promise they touched - `core/lifecycle/stages/release-candidate.md`'s "one package
per targeted platform" - is restated to what a shared build can honestly give.

## The flaky test, root-caused

`test_core_process.SilentChildInAStep.test_a_chatty_child_stays_running` failed on every
branch and on main (about 1 in 30 isolated runs). A probe that reproduced the test and kept
every sample and event, run under CPU load, captured it: the events jumped from
`…05.513Z` to `…08.295Z` while the driver's monotonic `elapsed_s` moved from 2.718 to 2.818 -
the wall clock stepped 2.7 s forward (a WSL2 time resync). `derive_liveness` judged output
silence as `now - last_output_at`, so a sample after the step and before the next recorded
heartbeat saw 2.7 s of silence from a child printing every 50 ms. The fix judges the silence
the driver measured (`last_heartbeat_at - last_output_at`, both stamped at one instant of one
clock) and keeps reporting the observer's view as `output_idle_seconds`. The watchdog that
cancels hung children always acted on the driver's monotonic `idle_s` and was never affected.

Evidence after the fix, same probe: 650 runs under load (up to 24 busy loops on 20 cores)
with 69 wall-clock steps observed and tolerated; 1 hung reading, in the first batch, that
did not recur in the following 570 runs and could not be captured - reported, not explained.
Before the fix: 2 in 19. The test itself, isolated, is recorded under Validation.

## The contract version, resolved

2.1.1 added `src/game/boot-scene.ts` to `SOURCE_PATHS` without changing `CONTRACT_VERSION`.
The module's rule said the version "changes whenever an entry is added", while its own
categories tie the version to acceptance. The entry is only recognized (the develop check reads
it to spot an import of the template's scene); a repository without it is refused nowhere. By
the categories no bump was due. The rule now says so, and every change is recorded
(`CONTRACT_LOG`) and enforced (`CONTRACT_DIGEST` over the entries, checked by
`test_template_contract`).

## Validation

The ladder is run on the merge commit and again on the release commit before tagging; the
result is recorded in the `v2.2.0` tag annotation and the GitHub release.

## What the evidence does not cover

- **Other portals' packages.** A CrazyGames or Yandex package needs a build of its own
  (template contract 2); until the Factory pins it, those platforms are reported not-ready and
  not packaged.
- **Device performance.** fps is still a desktop proxy (`PASS_MOCK`); no device was measured.
- **Portal behaviour, submission and publishing** remain outside the Factory
  (BLOCKED_EXTERNAL, behind G6).
- **The kill criteria** of a prototype stay unmeasured until real-player and real-device
  evidence can be recorded (the plan's MV-4 and MV-5).
