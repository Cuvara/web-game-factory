## What `/new-game` is

A **workflow entry point**, a new binding surface kind (`workflows:` in
`core/bindings/adapter-binding.yaml`), not a transition. `/web-game-factory:new-game` (and the
Codex adapter's `commands/new-game.md`) starts or resumes a run of
`core/workflows/new-game.workflow.yaml` through the existing engine — `bin/wgf new-game` /
`bin/wgf resume`, in the background — and reports it from `bin/wgf status`. The workflow file
stays the only step order, retry, loop, gate and resume logic; the command restates none of
it and composes no `/wgf-*` command.

```
/new-game  →  bin/wgf new-game (workflow engine)  →  core/workflows/new-game.workflow.yaml
/wgf-*     →  one lifecycle transition each (unchanged)
```

It never answers a gate. `wgf decide` and `resume --decision` run from the agent session would
be recorded as a person's decision (`default_decider()` sees no step process tree), so the
command refuses `--decision`, `--note`, `decide` and `--budget-*`, and at every gate or develop
handoff stops with the command the person types. It reports the configured autonomy without
changing `factory.yaml`, and asks before a real run whose init creates a GitHub repository.
`disable-model-invocation: true`: only a person starts one.

With the shipped `factory.yaml` a real run still waits at G2, G3 and the develop handoff,
and release refuses an unreviewed build. Unattended execution up to G4 is installation
config ([claude-capabilities.md](claude-capabilities.md)); G4 is always a person's.

## Why the Factory release is minor

One new adapter surface; no engine, workflow, lifecycle, gate, schema, configuration key or
template-contract change. The 13 `/wgf-*` commands, the agents and the skills regenerate
byte-identical. `check-integrity.py` gains a check of each `workflows:` entry against its
workflow file; nothing that passed before fails.

change, stated reason: the plugin could not run outside the repository. So the release was
held to the golden runs, on the tree that ships.

## Unreleased (after 2.4.1): a game idea for `new-game`

`/web-game-factory:new-game "3D goalkeeper game where the player blocks penalty shots"` - and
`bin/wgf new-game [--project ID] "IDEA"` - start a run anchored to that idea. Before it, the
Factory had no field for an idea anywhere: the CLI took no positional argument, `RunRequest`
and the run state had only `project_id` (identity), research was a catalog screen that
"never asks for, or needs, a game idea", and no schema had a place for one. So a quoted
idea was not dropped by the surface; there was nothing to carry it.

| | |
|---|---|
| CLI | one optional positional `IDEA` on every run command; refused (exit 2) when empty, over 500 characters, with control characters, with `--resume`/`--run`, or on a slice that runs no research step. `--project` is unchanged and independent |
| Run state | `params.idea`, canonical (`api.canonical_idea`), recorded in `WORKFLOW_STARTED` and a `GUARDED_PARAMS` entry: resume keeps it, an edit of it is refused. `wgf status` shows `Idea:` |
| Research | `scope.brief`, a question naming the idea, candidates ranked by `idea_match` (its words in the archetype's vocabulary, then the dimension it names) before the screen; an `idea-unmatched` gap when the selection holds none of its words or renders in another dimension; `opportunity.brief` |
| Strategy / design | `title-strategy.brief` (and the one-liner), `game-design.brief`; the built-in design author fits its archetype with the brief; the `agent` author is told to design the game it describes |
| Schemas | additive: research-report 1.1.0, opportunity 1.1.0, title-strategy 1.2.0, game-design 1.4.0 |
| Surfaces | both `new-game` surfaces take the idea as one verbatim argument after `--`; adapter binding unchanged (1.5.0: no surface added or removed) |
| Without an idea | params, artifacts and report ids are exactly as before: the blank market scan |

What it does not do: the catalog has no goalkeeper, and nothing is invented to pretend it
does. Such an idea selects the nearest shape of the dimension it names, the report says so
(`idea-unmatched`), and the built-in design author - which has no goalkeeper either - is held
by the design consistency rules to the mechanics G2 approved: its design is kept as evidence
and routed `descope`. The `agent` design author is the path to a design of the idea itself.
