## Why the Factory release is minor

New capability on the existing surface - an idea argument, an opt-in profile, `wgf where`'s
new fields - and four additive schema versions. Nothing an existing installation relies on
changes: without an idea a run's params, artifacts and report ids are exactly as before, and
the shipped configuration is still supervised. The one behaviour change is deliberate and
recorded: research no longer selects a concept design cannot build (9 of 11 catalog
concepts), which before this ended every such real run at design.

## A game idea for `new-game` (#16)

`/web-game-factory:new-game "3D goalkeeper game where the player blocks penalty shots"` - and
`bin/wgf new-game [--project ID] "IDEA"` - start a run anchored to that idea. Before it, the
Factory had no field for an idea anywhere: the CLI took no positional argument, `RunRequest`
and the run state had only `project_id` (identity), research was a catalog screen that
"never asks for, or needs, a game idea", and no schema had a place for one. So a quoted
idea was not dropped by the surface; there was nothing to carry it.

| | |
|---|---|
| CLI | one optional positional `IDEA` on every run command; refused (exit 2) when empty, over 500 characters, with control characters, with `--resume`/`--run`, or on a slice that runs no research step. `--project` is unchanged and independent |
| Run state | `params.idea`, canonical (`api.canonical_idea`), recorded in `WORKFLOW_STARTED` and a `GUARDED_PARAMS` entry: resume keeps it, an edit of it is refused. `wgf status` shows `Idea:` |
| Research | `scope.brief`, a question naming the idea, candidates ranked by `idea_match` (its words in the archetype's vocabulary, then the dimension it names) before the screen; an `idea-unmatched` gap when the selection holds none of its words or renders in another dimension; `opportunity.brief` |
| Strategy / design | `title-strategy.brief` (and an assumption naming it), `game-design.brief`; the `agent` design author is told to design the game it describes; the built-in author fits the buildable concept research selected and records a dimension mismatch with the brief in `open_questions` |
| Schemas | additive: research-report 1.1.0, opportunity 1.1.0, title-strategy 1.2.0, game-design 1.4.0 |
| Surfaces | both `new-game` surfaces take the idea as one verbatim argument after `--`; adapter binding unchanged (1.5.0: no surface added or removed) |
| Without an idea | params, artifacts and report ids are exactly as before: the blank market scan |

What it does not do: the catalog has no goalkeeper, and nothing is invented to pretend it
does. Such an idea selects the nearest buildable concept of the dimension it names
(endless-runner), the report says so (`idea-unmatched`), and the built-in design author -
which has no goalkeeper either - designs that concept (a 2D lane runner, consistency pass)
and records that the brief names 3D. The `agent` design author is the path to a design of
the idea itself.

## The autonomous profile

See [autonomous-runs.md](autonomous-runs.md). The shipped defaults (`developer: handoff`,
`reviewer: none`, no auto-approved gate, `init.source: github`) are unchanged. A project copies
`workspace/config/profiles/autonomous.yaml` to its own `workspace/config/factory.yaml`, now
layered over the shipped file key by key: the verified headless developer and read-only
reviewer, G2/G3 auto-approved, a local init with no GitHub repository, and a budget of 12
developer sessions / US$60. G4, G6 and G7 stay human; research still needs evidence.

## What this release does not cover

- No real (non-mock) end-to-end run: the autonomous profile was exercised with the real
  research, strategy, design, tech-plan, local init and assets steps, stopping before
  `develop`, the first step that starts paid agent sessions. The developer and reviewer
  argvs are the ones [claude-capabilities.md](claude-capabilities.md) records as run live.
- Two catalog concepts are buildable (`endless-runner`, `match-3`); an idea outside them is
  matched to the nearest buildable one and reported `idea-unmatched`, not designed as asked,
  unless the `agent` design author is configured.
- The Codex adapter still runs from the factory repository root. Windows was not re-run.
