# web-game-factory 2.8.0: a build held to its knowledge, its accepted baseline and its own pixels

Released 2026-10-14. Template: the pin moves to **web-game-template v1.2.1** (`4b74b08`), the
1.2 line's platform SDK fixes; template contract unchanged (1).

## Why this release exists

2.7.0 made the content a contract. The two validation games then showed where the Factory still
believed what a build said about itself: a repair counted as verified on a different scenario
than the one that failed; a lesson learned once was not carried to the next session; a judge's
pass that still listed the defect counted as a repair; the physics checks read only the
collider the game reported, so a game could pass them with a ball drawn twice its collider; a
candidate could drop levels a person had accepted and nothing compared it with that build; and
every per-platform bundle carried every portal's SDK, which CrazyGames rejects.

2.8.0 closes each of those, in the place it belongs. Nothing here is a new gate on a game
already past G4; every change is held by tests that fail on the defect it closes.

## What changed (details in [CHANGELOG.md](../CHANGELOG.md))

- **Knowledge as rules (K1-K5).** Lessons are rules with a domain, principle, anti-pattern,
  classification and revision; a run pins its knowledge contract and is held to it, a person's
  exception is the run's own record, and the design agent records which rules it applied
  (`knowledge.trace_matches_design`). First transferred principle **L29**: after the opening
  unit, a unit introduces at most one new element. See [knowledge-enforcement.md](knowledge-enforcement.md).
- **Closed-loop quality (K6).** Repairs are verified on the scenario that failed; the quality
  assessment answers three separate questions and says how each was measured; a lesson's
  evidence strength is derived from the finding ledger; the golden loop drives a real build
  through triage and the ledger with a planted defect and a negative control, no LLM.
- **Baseline comparison (K7).** `baseline.*` checks hold a candidate to the build a person
  accepted (`core/reference/baseline-compare.yaml`, `floor.accepted_baseline`); an unplayable
  accepted build never yields PASS, a dropped unit, field or entity fails, degraded plays are
  never cached. See [baseline-comparison.md](baseline-comparison.md).
- **Measurement integrity (K7).** A contact test freezes the 2D page where a mover turned and
  two checks read the pixels: `physics.contact_drawn` (hard) and `physics.drawn_extent`
  (quality); five bypasses closed (`play-realism.yaml` 1.2.0).
- **Triage hygiene (K7).** A failing judge report always blocks; a passing report's own
  findings are recorded as `noted`, never routed; a pass the judge still lists is no repair
  (`evidence-strength.yaml` 1.3.0, `specialist-routing.yaml` 1.7.0).
- **Platform preflight (K7).** `platform.foreign-sdk:<id>` and `platform.sdk-loaded:<id>` scan
  each package (`core/reference/portal-sdks.yaml`), with the publication guards
  `portal_sdk_isolated` and `portal_sdk_loaded`; a missing, unknown or blocked check is never
  green. Not required checks (a separate decision).
- **Template pin v1.2.1.** One adapter per platform build, Yandex rewarded video counted as
  shown without `onClose(wasShown)`, a Y8 capped break not counted as shown, generic-web in
  every build.
- **Publishing.** Per-platform submit behind G6 and a person's submit decision; publication
  profiles 2.1.0; GameDistribution and GamePix modeled (GamePix has no template adapter yet).

## What was validated, where

- **Linux CI (acceptance.yml)** on each merged head: check-integrity, schemas, adapters, the
  unit suite and `WGF_GOLDEN=1 bin/wgf test-core --strict` with both golden runs. On the final
  K7 head `3fcf95d` (run 38503114285): unit 4842 tests OK (132 skipped); test-core every
  category PASS, 2D GOLDEN 12/12, 3D GOLDEN 12/12 (62 tests skipped inside PASS categories,
  as before). K6's golden loop (greybox and develop stages) passed on PR #61.
- **Windows** full `unittest discover`: only the known Windows failures (paths, the pnpm
  shim, Blender), recorded per branch in the K7 checkpoints; Linux CI is the gate.
- **Template v1.2.1**: its release workflow (CI, verify, poki compliance, freeze) passed on the
  tag; CrazyGames, Yandex and GameVui workflows green on `4b74b08`.

## What the evidence does not cover

- **No live `/new-game` run on 2.8.0.** No paid agent session was run for this release; the
  real-quality comparison of a newly generated game is the next step, by a person.
- **3D golden flake** ([#67](https://github.com/Cuvara/web-game-factory/issues/67)): the act
  test's pause frame can race a crash on a slow runner and fail visual QA; reruns pass.
- **Known risks recorded in the K7 docs**: an honest broken composite face can be unmeasured
  and hold release; a collider inflated up to about 1.5x can pass; the contact bars come from
  one game; a not-reported baseline item on a busy host is a required FAIL at release.
- **2.7.0 was never tagged on GitHub**; 2.8.0 includes everything listed under 2.7.0.

## Upgrading from 2.7.x

No configuration change for a supervised installation. Runs already started keep the knowledge,
policy and profiles they pinned. A game created on template v1.2.0 keeps its pin; bringing it
forward is applying the template's 1.2.1 patches in the game repository. Update the plugin
(`claude plugin marketplace update cuvara`, then `claude plugin update
web-game-factory@cuvara`) to get the 2.8.0 runtime.
